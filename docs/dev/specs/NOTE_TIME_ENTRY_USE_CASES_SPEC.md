## 1. Scope

**In scope:**

- `workmain/services/notes_service.py`: `create_note` and `apply_cf_hook_on_create` become operations on an entered unit of work, and the use case `add_note` is added.
- `workmain/services/time_entry_service.py`: `create_time_entry`, `create_paired_time_entry` and `link_condensed_note` become operations, and the use cases `log_meeting_time` and `log_task_time` are added.
- `workmain/services/meetings_service.py` (new): the use case `record_condensation`.
- `docs/ARCHITECTURE.md` §2 Application: the line for `workmain/services/meetings_service.py`.
- `workmain/services/clockify_service.py`: `apply_pull` takes a unit of work from its caller.
- `workmain/database/repositories/meetings_repo.py`: `MeetingsRepository.set_condensed_summary` is added.
- `workmain/database/repositories/notes_repo.py` and `workmain/database/repositories/time_entries_repo.py`: the signatures of `NotesRepository.create` and `TimeEntriesRepository.get_by_meeting` move to built-in generics (DR9), with no change in behaviour.
- `workmain/ai/note_condenser.py`: `NoteCondenser.condense_meeting` stops writing the meeting.
- `workmain/orchestration/action_executor.py`: `ActionExecutor` takes no session and owns a scope for each call.
- The call sites: `workmain/cli/commands/notes.py` (`notes_add`, `notes_log`), `workmain/cli/commands/meetings.py` (`track`, `condense`), `workmain/cli/commands/time.py` (`time_add`), `workmain/cli/commands/clockify.py` (`_pull_entries`), `workmain/daemon/daemon.py` (`_execute_action`), and `workmain/integrations/slack/slack_eod.py` (`_execute_and_reprompt`).
- `tests/mocks/fake_unit_of_work.py` and `tests/test_fake_unit_of_work.py`: fakes and contract tests for every repository method the operations call (§2 row R14).
- Every test that calls a changed function or constructs `ActionExecutor` (§2 rows R3, R11, R12).
- `CLAUDE.md` § Note Write-Path Convergence is deleted. Its citation in `docs/ARCHITECTURE.md` §2 Application, and the "write-path map" `docs/standards/README.md`'s opening paragraph names as `CLAUDE.md`'s, are removed.

**Out of scope:**

- The rest of each command (its reads, decisions and printing). That is #208, #209 and #216. Each command changed here still prints as it does today, with `click` or with Rich's `console` and `err_console` (`meetings track`, `meetings condense`: `workmain/cli/commands/meetings.py:41-42`), and still reads through its own `session_scope()`.
- `notes_service.update_note` and `apply_cf_hook_on_tag_update`. They serve only `notes edit`, which #209 converts (design study F4).
- The condenser's queries, and the models it is handed. Both are #208's under `docs/ARCHITECTURE.md` §3, "Capabilities fetching their own data". This spec removes only its write.
- `clockify_service.classify`, `plan_entry_push` and `_record_clockify_link`. The first two are #281's. The third takes no session, and `push` shares it.
- Dating a meeting's notes by the meeting (#141). Whichever of #141 and this spec lands second re-reads the other's call sites (issue body § Scope).
- The `ActionExecutor` handlers' own logic. Only where each one gets its session or unit of work changes.

## 3. Design rules

- **DR1 — Operations take an entered unit of work.** `notes_service.create_note`, `notes_service.apply_cf_hook_on_create`, `time_entry_service.create_time_entry`, `time_entry_service.create_paired_time_entry` and `time_entry_service.link_condensed_note` take `uow: UnitOfWork` as their first parameter in place of `session`. They reach the database only through `uow`'s repositories, and never enter, exit or build a unit of work. Their other parameters and their behaviour are unchanged, except `link_condensed_note`'s, which DR3 states. Every signature this spec states, and every signature line a step adds or changes, is written in `docs/standards/3-code.md` §3.5 form; a line a step leaves alone keeps its form, since `automation/style_check.py` checks changed lines.
- **DR2 — A use case enters the unit of work its caller builds.** Each use case DR4 names takes a `UnitOfWork` not yet entered as its first parameter, enters it at most once with `with uow:`, and calls only operations inside it. `apply_pull` is the one use case that may return without entering it, on its skip and link paths (DR4). It returns a frozen dataclass whose fields are built inside the `with` block from plain values, never a model. `apply_pull` is exempt for the outcomes it builds outside the `with`: its skip and link outcomes, and the import path's `failed` outcome (DR4). A use case never calls another use case, and never builds a unit of work (`docs/standards/4-database.md` §4.1).
- **DR3 — Use cases take ids, not models.** No use case has a parameter annotated as, or passed, a model from `workmain/database/models.py`. `link_condensed_note`'s signature becomes `link_condensed_note(uow: UnitOfWork, meeting_id: int, condensed_note: Note) -> tuple[TimeEntry, bool]`. It loads the meeting with `uow.meetings.get_by_id`, raises `ServiceValidationError` naming the id when there is none, and otherwise behaves as today. Its `condensed_note` is a model created in the same unit of work by `create_note`, so it never crosses a session.
- **DR4 — The use cases.** Each grouping is exactly one use case:

  | Use case | Module | Signature | Calls | Returns |
  | --- | --- | --- | --- | --- |
  | `add_note` | `notes_service` | `add_note(uow: UnitOfWork, content: str, tags: list[str] \| None = None, source: str = "ad-hoc", meeting_id: int \| None = None, project_id: int \| None = None, created_at: datetime \| None = None) -> CreatedNote` | `create_note` | `CreatedNote(id: int, content: str, display_tags: str)` |
  | `log_meeting_time` | `time_entry_service` | `log_meeting_time(uow: UnitOfWork, meeting_id: int, content: str, tags: list[str] \| None, duration_hours: float, entry_date: date, entry_time: time, category: str \| None = 'meeting', project_id: int \| None = None, created_at: datetime \| None = None) -> CreatedEntry` | `create_note` with `source='meeting'`, then `create_paired_time_entry` | `CreatedEntry(entry_id: int, note_id: int, content: str, duration_hours: Decimal, display_time: str)` |

  Each result type is defined in the use case's own module, beside it (`docs/ARCHITECTURE.md` §1, Result types). `apply_pull` enters `uow` on its import path and nowhere else. The link path keeps `_record_clockify_link`, and the skip paths write nothing. Each path returns the outcome it returns today. A failure on the import path rolls back `uow` and is caught outside the `with`, as `docs/standards/4-database.md` §4.1 places a recovering handler, and becomes today's `failed` outcome.
- **DR5 — No use case runs inside an open scope.** Every caller builds one `UnitOfWork` for each use-case call, after any `session_scope()` it opened has exited, and opens a new `session_scope()` for anything it reads afterwards. `_pull_entries` builds `UnitOfWork(record=True)`, because the pull's import records an outside action (`docs/standards/4-database.md` §4.3). Every other caller builds `UnitOfWork()`. A caller reads the values it needs from its scope as plain values, ids and strings, before the scope exits (`docs/standards/4-database.md` §4.2). `notes add`, which today reads the meeting through `note.meeting` after the write (R10), reads its `id`, `title`, `start_time` and `end_time` with `MeetingsRepository.get_by_id` in its scope before the write.
- **DR6 — The condensed summary is written by the use case.** `NoteCondenser.condense_meeting` returns the same tuple it returns today, and writes nothing: it neither sets `condensed_summary` or `condensed_at`, nor flushes. `record_condensation` writes both columns, the condensed note and the linked entry, so all three commit together or none does. `MeetingsRepository.set_condensed_summary(meeting_id: int, summary: str, condensed_at: datetime) -> Meeting | None` sets the two columns on the meeting, flushes, refreshes and returns it (`docs/standards/4-database.md` §4.3), or returns `None` when no meeting has the id. `record_condensation` raises `ServiceValidationError` naming the id when it returns `None`.
- **DR7 — `ActionExecutor` owns a scope for each call.** `ActionExecutor()` takes no arguments. `execute(action)` keeps its signature, return type and dispatch. A handler that builds a repository runs in a `get_db().session_scope()` that `execute` opens for that call, inside the `try` that turns a handler's exception into a failure `ActionResult`, so a failure of that scope's commit is handled the same way. A handler that writes a note or a time entry builds one `UnitOfWork()` and calls `add_note` or `log_task_time`, with no scope open. An exception from a handler leaves its scope or unit of work, which rolls back, and `execute` turns it into the failure `ActionResult` it returns today. `ActionExecutorError` still propagates. `_execute_create_time_entry` parses the start time with `workmain.utils.time_parser.parse_time`. `workmain/daemon/daemon.py` `_execute_action` and `workmain/integrations/slack/slack_eod.py` `_execute_and_reprompt` call `ActionExecutor().execute(action)` with no scope around it, and keep their exception handling.
- **DR8 — Behaviour is unchanged at every entry path.** Each command prints, prompts, exits and writes what it does today, in the same order. Four exceptions, all intended:
  - a scope that today commits before a prompt (`notes.py:340`, `:658`; `time.py:333`, `:349`) is closed instead, because nothing is left in it to commit;
  - the condensed summary commits with the note and entry (DR6);
  - on both condense paths, `✓ Note created (ID: N)` (`notes.py:681`, `meetings.py:892`) prints after `record_condensation` returns, before the entry line, so when the use case fails nothing about the note prints and the failure message follows the lines printed before `record_condensation`;
  - when an `ActionExecutor` commit fails, the daemon and Slack post the failure `ActionResult`'s `Error: …` message (DR7). Today the caller's scope raises: the daemon posts "An unexpected error occurred. Please try again." and stops (`daemon.py:491-502`), while Slack posts "An unexpected error occurred.", then the success `result.message` it assigned before the commit, and calls `_maybe_post_correction_summary` (`slack_eod.py:467-478`). The change also removes Slack's false success message.

  `notes log` calls `add_note` once per line on a unit of work of its own, so a failed line is reported and rolls back alone, as its savepoint does today.
- **DR9 — Fakes answer as the real repository does.** Each repository method an operation calls has a fake in `tests/mocks/fake_unit_of_work.py`, with the real method's name and signature, and a contract class in `tests/test_fake_unit_of_work.py`, parametrized over `real` and `fake`, covering every outcome the operations rely on. These include the client-project `ValueError` in `TimeEntriesRepository.create` and `update`, `get_by_meeting`'s ordering by date then time, `ensure_active`'s idempotence, and `None` from `get_by_id` and `set_condensed_summary` for an unknown id. The methods are the six R14 lists as not faked, plus `MeetingsRepository.set_condensed_summary`. `FakeUnitOfWork.REPOSITORIES` gains `time_entries` and `meetings`. Each new fake repository's docstring states its row shapes. The `meetings` rows gain `start_time`, `end_time`, `condensed_summary` and `condensed_at`, which existing seeds that never reach `FakeMeetingsRepository` may omit. `TestFakeParity` compares each fake's signature to the real one's with `inspect.signature(..., eval_str=True)`, where `typing.List[str]` and `list[str]` are unequal, and `automation/style_check.py` rejects `List[...]` on a changed line. So the two real signatures that use `typing.List`, `NotesRepository.create` (`tags`) and `TimeEntriesRepository.get_by_meeting` (its return), move to built-in generics in Step 1, every line of each signature in §3.5 form, and the fakes copy them. `typing.Optional[X]` and `X | None` compare equal, so no other faked signature changes.

Anything a step meets that these rules do not decide is a departure (`.claude/skills/session-start/SKILL.md` § Role 3).

## 7. Risks and rollback

- **A call site left inside its scope.** On a real connection, a use case under an open scope would hang where the caller holds a lock it needs. In tests it would raise instead (R13). AC3.1 covers every entry path in R2 and R4, so such a site fails the suite rather than reaching production.
- **The condenser change reaches EOD.** EOD's condense step runs `workmain meetings condense` as a child process (`workmain/workflows/eod_workflow.py:226-227`). It reaches the condenser only through that command, which Step 3 converts. A child that fails after the condenser leaves no summary, so EOD offers the meeting again, which today's grouping also guarantees.
- **`ActionExecutor` in the running daemon.** The daemon loads code at start. Until close-out restarts it, it runs the old executor against the old callers, which is consistent. Step 2 changes both together.
- **Rollback.** Each step is one commit. Reverting step 3 restores the session forms and their callers. Steps 1 and 2 stand on their own, so either can be reverted after step 3 is.
